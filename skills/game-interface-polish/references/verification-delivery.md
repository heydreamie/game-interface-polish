# 验收、构建和交付

只展开当前改动相关的项。目标是验证可观察结果，不是按固定数量重复测试。

## 三种证据分开

| 证据 | 能证明 | 不能据此声称 |
| --- | --- | --- |
| 源码与配置检查 | 加载路径、事件处理、导出清单、候选风险 | 真实画面已经正确 |
| 测试/导入/构建日志 | 对应命令和覆盖范围通过 | 手机裁切、音效或观感通过 |
| 实际渲染、操作、播放 | 观察到的尺寸、状态、交互或声音 | 所有设备、性能或无障碍均通过 |

## 游戏检查

在真实浏览器检查相关桌面与手机尺寸，等待新素材实际加载；引擎画面可额外用原生渲染检查。无浏览器能力时完成能做的验证并明确边界，不用原生截图冒充网页验证。

查看信息层级、中文实际字形、长台词、角色与家具比例、地面、裁切、遮挡、加载和核心操作。章节切换、暂停/恢复、选择、重放与结束按改动相关性覆盖；全局快捷键也要在按钮、菜单和选择焦点中试。

导入修订或局部引擎融合时，确认当前选定基线的保留项，并走通“目标章节 → 未修改章节 → 返回”；要求引擎实际运行时检查实例与有效画面呈现，不以图片复用或静态截图替代运行证据。快速切章时也要检查异步旧画面不会回流。

保留能代表本次版本的截图；前后对比使用相同尺寸、状态和文案。旧截图或GIF不能作为新背景已接入的证据。浏览器DPI/缩放/旋转变化后若有异常，先定位CSS尺寸、逻辑舞台、物理画布的关系，记录重载可恢复等限制，不据固定尺寸通过宣称旋转兼容。

修复消息或选择遮挡时，除手动跳过外，至少检查受影响演出的一次自然结束。同时记录元素实际透明度、消息与字幕矩形关系，以及滚动到最新消息的状态。临时验收页可用于可重复的最长文案和边界位置测试，但标明其用途，再用实际游戏入口检查集成；不把临时按钮、虚构验收对白或测试入口混入游戏发行包。

## 导出检查

- 先区分当前源码、运行中的服务、`build`与ZIP版本。替换资源后重建受影响目标，再让预览载入新构建；避免只打包或展示旧产物。
- 交接网页与可编辑引擎工程时，说明体验与再制作分别需要什么；只体验网页不要求安装编辑器。给出按当前工程验证的本机HTTP启动方式，不能把双击HTML当成完整运行条件。
- 使用明确文件清单或已检查的导出配置。保留启动入口、必要资源、版本要求、说明及许可；排除个人配置、密钥、日志、缓存、用户目录和无关原包。草稿与提示词是否交付按用途决定。
- 先检查待提交差异，再检查实际归档内容。压缩包校验通过只证明未损坏；源码包还要在新的空目录解压导入/启动，验证资源、字体及引用没有依赖本机路径。
- 可用清单与哈希核对当前源文件和归档文件一致，但不重写原始素材基线来掩盖变化。界面修复不能把完整剧情换成演示前半段；核对章节、终点和分支范围。另存的历史包和当前下载链接要分清版本。
- 对最终独立版做启动检查；Web产物通过HTTP打开；视频验证最终媒体文件。测量资源体积并如实报告，不把本机压缩率或空闲帧率变成公网性能承诺。
- 使用当前壳层处理文件。PowerShell的外部命令失败后不一定自动终止，检查`$LASTEXITCODE`再继续提交或打包；日志路径优先使用已确认可写的绝对路径。
- Git仓库仅在确定的代码项目根目录操作。用户已有修改不清理；运行相应验证、查看差异后小步提交。源码导出不等于允许推送或部署。

## 平台发布与大引擎文件

仅在用户授权发布时处理。先核实平台的真实单文件/包体限制，再决定压缩、拆分或其他受支持方案；仅改扩展名或包成ZIP不能证明可加载。gzip链路检查服务器是否已自动解压、客户端是否重复解压、WASM响应/加载器是否匹配，并启动实际引擎验证。

使用Sites时按可用的`sites:sites`指导操作正确站点，保留既有访问范围，根据发布工具的完成状态给链接。其他平台使用其实际工具与约束，不写死案例站点ID。

交接包不默认携带原线上发布绑定或凭据；需要接管同一站点时按用户明确要求保留必要的非敏感配置，并说明凭据如何另行提供。遇到被拒绝的大对象或提交历史问题，先报告并在现有授权内处理，附件旧记录不授权重写Git历史。

## 最终输出形状

```text
已完成：本次实际接入的改动和当前交付类型。
已验证：命令/真实观察及其尺寸和关键状态。
打开/下载：能使用的入口、源码或成片，附当前版本画面。
待验证：实体设备、读屏、配音审听等实际未覆盖项（仅列有关的）。
```

用户只要素材时无需改游戏；用户要求替换时接入并重建；用户只要源码时校验并交付当前源码包，不重跑与版本一致性无关的整套流程。
