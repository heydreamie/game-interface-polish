# 界面分层、对白与消息排版

用于既有游戏的局部换肤、入口接入、气泡过窄、微信被字幕挡住，以及自动播放后看不见选择的情况。沿用当前架构，先复现再修改。

## 借用画风与接入页面分别处理

“按这份源码的风格优化边框”通常意味着提取纸张、配色、描边、阴影、按钮和字体规则，应用到当前游戏外壳。不能自动增加首页、商城、文字故事编辑器，或把整套参考网站替换进来。

涉及首页和案例入口时，先从当前会话与源码列出实际去向：主按钮、案例卡片、游戏入口、返回入口。主按钮文案与去向是两个独立约束；用户只要求案例卡片接入游戏时，保留主按钮原文和原去向，卡片封面、标题区和箭头指向同一游戏入口，返回入口可落回案例列表。存在影响产品结构的真实歧义时只问这一项，其余局部修复继续进行。

舞台内部绘本背景、舞台纸框、整页外侧底图、字幕/消息等是不同层。用户要求“边上垫这张图”时，将图接到外侧留白层，不覆盖剧情场景；需要时给内容区浅色衬纸。直接使用提供的成图不需要重新生成。原本动态的背景仅做风格处理时，保留云、窗景、吊环等实际动画消费者。

中文字体保留明确的无衬线回退，联合检查字号、行高和可用行宽。参考图中的固定尺寸与色板只适用于对应项目。

## 对白气泡被压成窄列

先读取气泡、人物容器和舞台的实际矩形。绝对定位子元素采用自动宽度、左侧定位为人物中点时，可能按人物剩余宽度收缩；仅提高 max-width 不一定有效。

- 让对白宽度由整句内容和舞台可用空间决定，避免随人物图片宽度缩小。
- 打字开始前按完整台词测量并预留宽高，显示部分文字时维持该尺寸，避免气泡反复伸缩或换行。
- 将气泡矩形限制在舞台边缘内，尾巴仍指向实际说话者。不要只把整个气泡居中却指向错误人物。
- 图片加载后、换动作帧后和视口变化后重新定位；图片未加载时人物宽度可能为零，初次测量正确不代表最终正确。
- 长台词继续使用项目已有字幕或长对白方案，不为塞进小气泡而缩小字号或截掉关键台词。

用同一句长对白对比修改前后，检查左/右角色、靠边角色、首次资源加载和手机宽度。

## 微信与字幕互相遮挡

核对所有消息类消费者，例如实时消息框、聊天回忆框和对应可滚动正文；不要把人物手里的手机道具也当成消息浮层移走。

先查真实定位和堆叠上下文。固定在底部的微信框与底部字幕通常共享区域；单纯提高 z-index 会让字幕反过来被挡住。指定右侧或其他用户确认区域后，为字幕预留独立空间。

- 根据字幕当前实际高度和舞台尺寸计算消息区可用高度；不能只拿一行短字幕测试，或假定字幕永远固定高。
- 消息框按内容自然长高，以可用高度为上限。标题栏固定，正文可滚动；聊天回忆框同样支持查看完整记录。
- 新消息或尺寸变化后保持最新消息可见，平时允许手动滚动阅读旧消息。上层若默认禁用指针事件，给需要滚动的消息框恢复指针事件。
- 观察尺寸变化时避免循环触发重排。几何间距通过后，仍需看真实像素、文字和滚动状态。

验收：单条长微信、多条连续消息、聊天回忆与长字幕同时出现；桌面和手机均无相交、横向溢出，正文能滚动到开头和末尾。

## 自动演出结束后像是卡住

先区分：没有下一节点、等待玩家选择、面板存在却不可见、面板可见但无法操作。检查剧情状态、显示类、hidden、透明度、动画播放状态和上层遮挡，再定位根因。

场景暂停不应冻结所有后代动画。诸如“暂停舞台内全部动画”的规则可能把新选择面板的淡入停在透明度0。让背景、人物和剧情动作按故事时钟暂停，选择、反馈、复盘等界面入场保持可用；也可由状态直接控制界面最终可见状态。

必须让一段演出自然播放完，确认选择或“继续故事”实际可见且可操作。只手动跳过、只检查元素存在、只跑剧情图测试，都可能漏掉这一类问题。

标题或字幕出现局部模糊残留时，分别检查半透明底、backdrop-filter、入场动画与截图/浏览器合成行为。实色纸签通常不需要毛玻璃；修改后检查文字与背景，不把疑似合成问题直接认定为原图模糊。
