# 场景、动画与横竖屏

## 沿用合适的现有实现

先看项目依赖与现有动作系统。浏览器项目可沿用已有Canvas、CSS或游戏框架；用户选择Godot后才进入Godot路径。需要新选型时按目标平台、交互复杂度、资源与部署成本比较少量方案，核实官方资料，区分“文档支持”和“本地跑通”。

角色拆件PNG不等于可直接绑定的骨骼。检查关节、遮挡、重复肢体和透明边界；关节缺失时优先评估现有动作帧能否交付，并说明未支持的动作。位移加整图摆动不能称为完整骨骼或真实跑步。

## 角色先校准，再接状态

- 图集检查动作分组、帧顺序、循环、透明背景、画布尺寸和锚点。统一脚底基线；需要时校准头部水平位置，保留测量记录。
- 把舞台位置与角色局部姿态分开，避免走路位移和呼吸/倾听动画争抢同一变换。
- 剧情、帧动画、位移、姿态与特效使用统一推进时钟。暂停冻结所有相关动作，倍速同时作用；静态背景不必每帧重画。
- 动作优先级按项目明确。对叙事游戏可用“移动 → 未完成的手势 → 当前说话者 → 待机”；手势的完整时长不应被下一条短姿势节拍意外截断。
- 角色行走循环与位移速度协调；跳过节拍后仍落到目标位置。镜像方向是否可用需看衣着、道具和文字，不能一律翻转。
- Godot可用SpriteFrames承担帧动作、AnimationPlayer叠加姿态；这是实现选项，不是所有项目的必选栈。

## 剧情与输入要随画面一起验

保持原剧本、章节、选项和关键道具语义。章节回看不重复累计数值；同一答案重放可保留后续状态，早期改选则重算或清除受影响的后续结果。

键盘事件需结合焦点：普通播放可响应暂停/切章；菜单打开时方向键交给菜单，选择面板里的数字键或Tab/Enter走对应路径。把鼠标、触屏与快捷键接到同一个选择处理函数，避免一次输入重复结算。

手机隐藏侧栏时，检查侧栏里的消息、提示或任务信息是否仍有可见替代位置。装饰可以省略，剧情信息不能静默消失。

若在融合新动画/引擎时保留已有字框、打字与气泡，按[版本融合](version-merge.md)划分职责并检查章节往返；保留行为的要求不能被整套UI替换冲掉。

## 背景等比取景

把舞台、演员、地面与叙事道具当成一个构图检查。允许牺牲不重要的边缘，不拉长家具，也不以整图缩小掩盖比例问题。多人分屏需要各自保留有意义的空间。

普通背景采用覆盖取景时，可按以下关系计算：

```text
s = max(舞台宽 / 图片宽, 舞台高 / 图片高)
可见源宽高 = 舞台宽高 / s
源偏移x = (图片宽 - 可见源宽) × 水平关注位置
源偏移y = 源图地面y - 目标舞台地面y / s
```

关注位置根据场景选择，例如窗侧、电梯、白板或候车棚。源偏移y需处于`[0, 图片高-可见源高]`。若计算越界，说明当前缩放无法同时满足填满舞台与指定落地关系；调整缩放、取景/构图或演员位置，再检查实际投影，不能钳制后声称仍精确对齐。地面不统一的素材先各自标定。

地面线可能是“墙与地板的交界”，不一定是“脚必须贴合的细线”。例如源图地面82%、舞台目标地面82%、演员脚底88%，脚位于地板内可以合理。源图2400×1000、舞台360×400时，`s=0.4`、可见900×1000、源偏移y=0；交界线在328px，脚底在352px。若用户要求两线重合，偏移会变成-60而不可行，应重新构图或调整缩放；不能将这24px自动判为悬浮，也不能忽略真实画面判断。82%/88%均是案例值。

双空间通话在窄屏可将图片左右分开，各按自己的裁切窗口取景，再保持共同地面和明确分隔。裁切会漏掉关键剧情对象时，改布局、补独立竖版素材或让该对象独立绘制。

背景地面线以外还要检查演员原画是否带阴影、道具是否悬浮、台词是否压到脸、标题是否与背景线条混在一起。优先调整取景和信息位置；必要时给小字浅色底或描边，并实际查看。

## 按阶段看动画

查看待机、说话/倾听、移动中段、动作结束、跳过、暂停恢复、倍速、选择等待和章节跳转。对战画面还应查移动/攻击方向、命中与碰撞、死亡/失败/胜利互斥；不能以结尾文字宣称与画面相反的结果。
