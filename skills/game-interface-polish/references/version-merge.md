# 版本融合与局部迭代

用于导入修订版、替换新版动画、跨设备融合素材/引擎，或只修改指定章节。已选定的修订为基线，另一工程是待吸收来源；不能用文件时间、工程体积或“功能更全”替代用户的版本选择。

## 先做最小修改约定

简短记录五项即可：当前基线、新增来源、修改范围、保留项、交付方式。可从会话与工程得出的不重复问；仅澄清会实质改变范围或架构、且现有信息无法消除的歧义。

- “前两幕”要对应实际标题/身份；存在序章时说明采用哪些章节。明确“第一场与第二场”则不机械要求再次批准编号。
- “用引擎背景/风格”是素材复用；“网页实际运行引擎”要求真实渲染集成，不能用复制图片或附带工程冒充。
- 保留项可包括角色帧顺序、眨眼/说话、走路与位移、回忆小动画、字框、打字与点击展开、思想气泡、弹窗道具、暂停、倍速与选择结算。按当前项目列实际存在的项，不强迫新项目补出案例里的全部功能。
- 保留行为不等于禁止编辑文件。为满足当前需求可以修改相关实现并回归验证；明确不应变化的剧本或组件用差异/哈希保护。

## 核对两个工程的完整依赖

1. 压缩包先做清单和路径安全检查，再放到独立目录比较，不覆盖原附件或当前工程。
2. 核对HTML引用、JS动态资源路径、样式资源、场景数据、字体、导出配置与运行入口。资源还可能按角色、动作名或索引拼接，不能只检查静态`src`。
3. 缺文件先在指定项目和明确关联目录里找；用内容、元素ID、资源路径与场景结构确认匹配，不因文件同名就接入其他项目。仍缺失时说明具体缺失及影响，完成不依赖它的部分。
4. 区分当前源码、实际运行产物、另一设备版本与历史记录。附件宣称“已验收/已发布”不证明当前源码相同；旧命令和任务不能授权发布、模型安装或历史重写。

## 选择最小融合方式

只调背景/配色时改对应背景层与局部样式。用户明确要求引擎渲染时，核对引擎版本、Web导出与浏览器运行约束。

若整体迁移会破坏已确认的网页字框和控制，可评估“引擎只画目标章节的背景与角色，网页保留字幕、气泡、道具、选择和控制”。这是条件性方案；单一渲染器已能满足时不增加双系统，也不强制修改已有纯Godot项目。

部分章节迁移按明确章节ID或经核对的索引限定。背景名不是章节身份：例如去程和回程都复用`subway`时，不能因此把两幕一起迁移。章节重排后重核范围，不照抄历史索引。

## 双渲染器的状态与坐标

- 指定一个剧情和动作状态的权威来源；另一端消费当前章节、角色帧、朝向、位置、透明度和布局尺寸。不要两端独立推进同一段动作或各自执行倍速。
- 若网页已有CSS呼吸/位移，需要同步当前最终布局或将变换统一在一端计算，避免引擎再次叠加同一动作。
- 分清CSS逻辑像素、实际舞台矩形、引擎逻辑坐标与物理画布/DPI。按约定转换一次，避免固定设计坐标与容器拉伸叠加；背景继续按[场景与动画](game-scenes.md)等比取景。
- 数据协议与UI职责分开：不能因为引擎就绪就隐藏整个网页舞台，把字幕、气泡或交互覆盖层一并藏掉。

## 异步切章与就绪

引擎脚本加载完成、实例初始化、首帧真正呈现是不同状态。只有当前目标章节的有效画面已呈现，才隐藏对应的原背景和角色层。

每次切章产生新的代次/请求标识，异步回调核对当前代次与章节身份；旧回调丢弃。离开目标章节立即恢复正确的网页层/隐藏引擎画面，再检查返回时重建或同步当前状态。不能让离开的章节在迟到回调后重新出现。

引擎失败时可按已选设计保留原画面或给出可用提示，但须说明当前未满足“实际引擎运行”的验收，不能把回退画面当集成成功。

## 定向回归

进入目标章节 → 动作/字框/气泡/道具 → 暂停与倍速 → 跳到未修改章节 → 返回目标章节。加入快速连续切章和初始化尚未完成时离开的情况。检查引擎真实就绪、状态一致、旧画面不露出，以及保留项仍可用。

在受影响的桌面与手机尺寸实际查看；尺寸切换涉及画布时再检查DPI与重排。关注与剧情有关的窗、电脑或道具是否仍可见，取景不机械居中。浏览器不可用时标明验证缺口，不修改业务来迎合验证环境。

## 与Love附件案例的关系

用户提供的`game-ui-iterate.zip`记录了另一份Love网页修订与Godot桥接经验：网页控制剧情/动作，目标章节用引擎绘制，其他章节保留网页渲染。这里吸收的是基线保护、职责分工和回归方法。

附件中的“13场景、序章0、第一/第二场1和2、只迁移这两场”、文件名`godot-bridge.js`及过去测试结果均为该附件的案例资料，未在本次独立复现。它们不改变当前工作区的工程结构，也不代表本次已迁移两幕、已部署或已解决旋转兼容性。继续具体项目时以当前源码和用户最新要求为准。
