# Remotion / Hyperframes：只纳入有用的部分

只有用户要求游戏风格视频、宣传片、录屏编排或MP4导出时进入此分支。Remotion和Hyperframes负责视频组织与渲染，不是既有游戏必须迁移到的引擎。纯游戏界面改造无需安装它们的运行依赖。

## 如何结合官方技能

| 场景 | 复用路径 |
| --- | --- |
| 已有React/Remotion视频工程 | 读取已安装的 `remotion-best-practices`，再按当前任务进入创建、markup、预览或渲染指导 |
| 已有HTML/Hyperframes视频工程 | 先读已安装的 `hyperframes`；CLI、组件复用、媒体按需读取 `hyperframes-cli`、`hyperframes-registry`、`media-use` |
| 只有正在运行的游戏，需要展示成片 | 先判断能否录制真实游戏；字幕、片头和剪辑可交给选定的视频工程，保留真实玩法与演示标签 |
| 没有视频工程 | 用现有素材与要求选择一套合适工具，不要求两套都运行，不自动转换用户已有工程 |

官方技能未安装时，可先交付不依赖它的部分；用户明确要求安装后，使用当前环境的技能安装流程。不要把本文里的历史安装命令当成永远有效的API，也不自动覆盖已有用户配置。

复用其技术约束与检查方法，不把自动反馈/遥测发送、云端发布、账号服务、可选大模型下载或产品推广变成当前任务的默认动作；这些行为依用户实际目标与既有授权判断。项目已固定工具和输出规格时继续沿用。

## 两套技能最值得迁移的约束

- **Remotion：** 视频里的动作由`useCurrentFrame()`及插值控制。网页中看似正常的CSS动画/transition不能直接当作视频动画已成立；改为帧驱动并验证实际渲染。这条用于视频工程，不要求改写普通可玩网页的CSS。
- **Hyperframes：** 场景与素材分开、媒体落为本地文件、建立暂停且可定位的时间轴。可编辑的文本/颜色/媒体参数保持可替换，避免把全片烘焙成一张图。
- **Hyperframes检查：** 读取结构化结果；当前官方指导中的`doctor`可能退出码0但`.ok`为false，`check`的“0 samples”也不表示画面已检查。查看渲染帧之后才评价布局。
- **共同方法：** 明确事件时间、查已有组件、看预览和关键帧、验证最终文件。它们服务游戏展示需求，不自动带入默认横屏比例、营销音轨、账号服务或发布步骤。

## 从视频技能吸收的生产方法

**环境分层确认。** Skill文件存在，只说明指导文件可读；另查项目所需Node/包管理器、浏览器渲染或编码工具、框架版本及媒体文件。先渲染小样或一帧确认最小链路。语音、识别、音乐模型与收费API仅在用户实际要求时引入，密钥不进入前端或导出包。

**一个可重复定位的时间轴。** 用框架当前支持的可寻址时间/帧驱动角色、镜头、字幕和效果。任意跳到同一帧应得到一致画面；不要依赖墙上时钟、未受控的随机数、异步未就绪素材或无法复现的后台计时器。涉及随机行为时固定种子或记录轨迹。

**先用已有组件。** 在选定框架的指导下检查现有组件和官方可编辑素材，再决定是否自行实现。可借鉴分镜、素材、时间轴、预览、渲染的结构，不为了使用组件而新增无关动效。

**游戏语义先于装饰。** 射击、跳跃、追赶、受击、碰撞和关卡结果要与画面可见事件一致。预设路线的视频也要验证事件轨迹；被击中后仍展示无伤通关需要修复轨迹或结果，不应只换结尾字幕。若是演示模拟而非游戏录制，在交付中说明。

**声音按需分层。** 旁白、对白、动作音效与配乐分开，事件音对齐事件帧；只有用户要求卡点时才围绕音乐节拍编排。检查说话停顿、字幕同步、声音峰值与遮盖。文件有音轨不等于已试听；无法听时说明。原版游戏音乐须核对当前用途的授权，不能把可找到当成可公开使用。

## 渲染与交付

沿已选框架的官方Skill执行当前有效的预览、检查与渲染命令。不要固定复制其他电脑的版本、端口或模型路径。

先查看开头、关键事件与结尾，再对已导出的文件确认时长、画幅、帧率、音轨、字幕安全区和资源是否缺失；需要时从头播放。修复后回查原问题点，并复核受影响段落。

成片验收不能代替可玩游戏的输入、分支、失败状态和触屏验收。交付分别标注“可玩工程”“游戏风格视频”“游戏录屏/剪辑”，并给对应路径；生成图片、声音或预览页均不等于已交付MP4。
